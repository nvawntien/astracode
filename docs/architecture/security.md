# Staging trust boundaries

App hosts the k3s server and protects its administrator and server credentials. Only the App activation issuer and secret loader can use their scoped host identities. The rollout service reads boot-bound authorization over an App-local Unix socket and updates named rollout objects. The credential loader holds only its designated secret access. The separate activation issuer holds the permit key and database fence login. Ordinary App workloads and Judge Worker receive narrowly scoped runtime credentials, private service access and no host credential mounts or general cluster authority. The Judge host joins with a rotatable agent-only token and has no Azure identity, Key Vault access, server token or administrator kubeconfig.

The offline candidate places the privileged platform-managed go-judge daemon inside the dedicated Judge VM's trusted computing base under Accepted ADR-0012. A daemon compromise can affect the host and shared cluster. The exception is confined to the authorized workload, artifact and placement. Worker remains unprivileged and accesses the executor privately. Live use requires the S3 isolation evidence specified in the ADR. [Accepted ADR-0012](adr/0012-judge-executor-trust-boundary.md) · [Kubernetes runtime and admission](../../infra/kubernetes/README.md)

Submitted and interactive code must remain confined by the executor's CPU, memory, process, time and output limits, with network and access to host and cloud credentials denied. Workload activation fails closed when current authorization is lost. Stale Jobs or controller objects convey no authority to run. [Managed activation](../../infra/azure/lifecycle/README.md)

Ingress is reachable only over the approved HTTPS path with client certificates and a current tester lease. The smoke route uses its own limited identity and CA. Envoy continues validating application JWTs and forwarding the verified identity. Backing services, the private APIs and the executor have no public service route. Verify the real managed network, identity and routing controls during S3.

The simplified M0-13 candidate separates owner window approval, manual infrastructure power, native GitHub deployment approval and App-local workload authorization. A slot-specific federated workflow identity can invoke Azure Action Run Command on App, which can execute as root on that VM. The GitHub workflow and App host are trusted for that authority. Restrict the subject to the exact repository, protected ref, environment and workflow, and prove VM power, Judge or state access is denied. The emergency deallocate-only identity and S4 publication and receipt scopes remain separate. Live authorization tests are pending.
