# Trust boundaries for M0-13 staging

App hosts the k3s server and protects its administrator and server credentials. Only the App poller and secret loader can use their scoped host identities. The poller pulls approval and updates named rollout objects. The credential loader holds only its designated secret access. The separate activation issuer holds the permit key and database fence login. Ordinary App workloads and Judge Worker receive narrowly scoped runtime credentials, private service access and no host credential mounts or general cluster authority. The Judge host joins with a rotatable agent-only token and has no Azure identity, Key Vault access, server token or administrator kubeconfig.

The platform-managed go-judge daemon is a trusted privileged component of the dedicated Judge host. Admission restricts the exception to its approved image digest, fixed workload template, namespace and Judge node. The pinned runtime configuration uses private namespaces and omits host block devices and runtime sockets. Worker-to-executor traffic stays on the Pod's loopback endpoint. A compromise of the daemon may compromise the Judge host and affect the shared cluster. Admission policies, NetworkPolicies and the launch guard provide no independent boundary against a compromised privileged daemon. See the [owner-approved decision](../../openspec/changes/azure-walking-skeleton/decision-judge-executor.md).

Submitted and interactive code must remain confined by the executor's CPU, memory, process, time and output limits, with network and access to host and cloud credentials denied. Guarded workloads require current signed permits tied to both startup epochs, the exact workload, image and configuration, and the container PID namespace. Loss of authority closes new process starts and ends currently guarded children. A stale Job or controller object conveys no permit. S3 verifies live packet and credential denial and actual limit enforcement for both official submissions and Run Code.

Ingress is reachable only over the approved HTTPS path with client certificates and a current tester lease. The smoke route uses its own limited identity and CA. Envoy continues validating application JWTs and forwarding the verified identity. Backing services, the private APIs and the executor have no public service route. Verify the real managed network, identity and routing controls during S3.

GitHub approval is bound to the typed request, registered workflow revision, native environment review, run and attempt. Separate identities authorize lifecycle, delivery and eligibility. The remote controller reconciles power only for the approved pair. Its emergency role can read and deallocate that pair. The S4 publisher can create receipts and cannot authorize staging. Phase A validation and local isolation observations are documented in the [evidence map](../evidence/m0-13-phase-a.md).
