# AstraCode staging delivery

M0-13 defines separate App and Judge VMs for S2 Staging and disposable S3 Testing. Terraform state, approved release receipts and environment data have separate scopes. Follow the [Terraform roots and pinned inputs](../../infra/azure/README.md), the [Kubernetes workload templates](../../infra/kubernetes/README.md) and [ADR-0004](adr/0004-azure-topology-and-subscription-layout.md).

## Azure topology

The selected configuration for S2 and S3 uses Korea Central and Ubuntu 24.04 x64. App runs the k3s control plane, ingress, application services and backing stores on `Standard_B4s_v2` with 4 vCPUs and 16 GiB RAM. Judge runs the k3s agent and its judging workloads on `Standard_B2ls_v2` with 2 vCPUs and 4 GiB RAM. Each node has a 64 GiB Standard SSD LRS OS disk. App has a separate retained 64 GiB Standard SSD LRS data disk. S4 shared storage uses the same candidate region. [Preflight observations and allocation status](../evidence/m0-13-phase-a.md#azure-preflight-observations)

The infrastructure plan arms the independent controller and monitors before compute creation. A reviewed plan and a current, target-bound controller window authorize creation or replacement. Routine power-off deallocates VMs, retains their network identities and preserves the App data disk. A capacity-constrained replacement recreates one VM after deleting its prior instance and reuses its network identity. S3 rehearsals use explicit experiment deadlines and two approved immutable releases. ## Release and operational lifecycle

For protected S2, the separate owner-reviewed default-branch maintenance PR registers workflows and retires the legacy hosted SSH/tag deployment entry point. Confirm the off window, forecast, operator access and identity separation before arming S2. A merged application SHA gets one canonical OCI bundle and write-once receipt after exact-SHA CI. The App retrieves the approved bundle with its protected poller. See [release publication and main transition](../../scripts/release/README.md).

1. The member submits the exact typed originating request and a distinct authorized member dispatches it where required. The owner approves start in `staging-lifecycle`. Check both VM states and the bounded boot deadline. Separately approve deploy in `staging-deployment` for the selected canonical digest. See [request fields and commands](../../infra/azure/lifecycle/controller/README.md).
2. The App validates the binding and records the operation before changing runtime state. It closes tester admission, quiesces judging, confirms the prior Submission exit and checks the three independent managed databases. The trusted fencer holds writer leases and checks the package, owner histories and schema. The host then opens the reviewed App templates, followed by the matching Judge workloads. Readiness, the private Problem contract, and the approved smoke journey must pass before opening the tester lease. See [managed activation](../../infra/azure/lifecycle/README.md).
3. The one-hour tester session starts at readiness. Require a new owner approval for a matching-generation extension that fits the off window. Approvals only affect their requested action. The independent controller closes new access at expiry or cancellation and drains or safely interrupts ongoing work, retains pending official work and confirms both VMs deallocated.
4. A failed or interrupted operation keeps tester and process activation closed. Identify the App and Judge VM and boot epochs, reconcile the old Job's actual exit and writer leases, compare all owner histories with reviewed prefixes and account for retained attempts, relay records, Kafka offsets and DLT. Use the separate reviewed recovery ticket for the exact prior attempt. A partly advanced schema requires a reviewed forward deployment or restore.
5. Roll back to a previously verified exact artifact only when all three live histories equal its pinned versions. The rollback runs without Goose DDL and reuses current credentials. Repeat the App-before-Judge readiness and smoke checks. The S3 and S2 drills still measure the 15-minute target.

The independent alert and emergency deallocate-only identity remain available through a controller outage. Confirm each VM's actual instance view. An uncertain prior start requires reviewed provider reconciliation before another start. Deallocation preserves S2 disks. S3 cleanup compares the approved experiment inventory, Terraform state and actual resources, then removes only reviewed disposable assets.

Production deployment is outside this change. Promotion eligibility checks the reviewed semantic-tag mapping against canonical S2 evidence and requires maintainer approval outside a contest freeze. The eligibility path only reads evidence.
